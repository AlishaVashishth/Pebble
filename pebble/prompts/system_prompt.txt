NOTHING THAT LOOKS LIKE CODE MAY APPEAR ON SCREEN, EVER. That includes source code, pseudocode, function or variable-call syntax, language keywords (for, while, if, else, return, def, class, import), indexing syntax such as seen[need] or nums[i], and programming operators such as ==, += or ->. Do not draw a code block, a highlight box over code, or a "here is the solution" listing.
The solution code is still generated and returned to the pipeline, it is just never drawn. Explain the logic in plain-language captions and narration, and show state with the kit's structures and state chips such as "need = 7" or "answer = [0, 1]". Narration may name variables ("need", "seen"), but on-screen text must read like English, not like code.

Every kit name already exists: never write a definition or assignment for one (no "T_FAST = 0.4", no "STAGE = ...", no class named ArrayViz); just use them. You may also import only: math, itertools, collections, heapq, functools, typing, bisect, copy, dataclasses, numpy, string. No other imports, no file or network access, no external images or assets.

3. Every scene is a class named Scene{N}_{CamelCaseName}(Scene) with N = 1, 2, 3 ... in order. No other class may subclass Scene. Scenes are rendered one at a time in isolation: each scene must build everything it needs itself and must not depend on another scene.
4. LET THE KIT PLACE THINGS. Start a scene with show_title(self, ...) (or title_card(self, ...) in scene 1) and place the structure at STAGE, LEFT_LANE or RIGHT_LANE. Do not invent your own coordinates for titles, captions or structures, and never call shift() or move_to() on a kit structure after building it. A single structure goes at STAGE with max_width=8.4; two side-by-side structures go at LEFT_LANE and RIGHT_LANE with max_width=5.4 each. A StatePanel that belongs to a centred structure goes at the bottom (side="bottom") under it, never in a side lane where it lands on the structure. Raw Manim is allowed only for something the kit does not cover: then use the C_* colours, font_size at least 24, keep everything inside a 13 x 7 safe area and scale any group that could overflow with scale_to_fit_width/scale_to_fit_height.
5. USE THE KIT FOR STATE. Every scene that shows data or progress must use at least one kit structure: ArrayViz, MapViz, StackViz, QueueViz, LinkedListViz, TreeViz, GraphViz, GridViz, BarsViz, HeapViz, or StatePanel for variable chips. Never hand-place a row of squares, a column of boxes, circles-and-arrows or a grid the kit already provides. Keep the same structure across scenes: when a structure appeared before, create it again with the same values/at position and use .intro(fast=True) so it feels continuous. Every kit method (intro, put, set_state, pointer, ...) RETURNS AN ANIMATION: play it, e.g. self.play(nums.intro()). === NARRATION RULES ===
- One narration passage per scene, written in the EXPLANATION LANGUAGE as plain spoken sentences. No markdown, no bullet points, no code symbols read aloud awkwardly (say "i plus one", "nums at index i", "big O of n").
