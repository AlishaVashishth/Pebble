KIT PLAYBOOKS (one per pattern; each beat is one narration sentence = one caption = one visible change)

These are teaching recipes for the kit, not drawing instructions. The illustrative
values below are only placeholders: the real values always come from your trace.
Pick the playbook that matches the problem and adapt the words; never draw code.

1. TWO POINTERS
   Beat 1 "Two friends start at the two ends": left and right pointers slide in (pointer.intro()).
   Beat 2 "We add what they hold": both cells amber, chips "left + right = 9" and "target = 9".
   Beat 3 "Too small, so the left friend steps right": the left cell turns red then grey, the
   left pointer slides one cell right (pointer.to), the new cell turns amber, the sum chip updates.
   Beat 4: the mirror case for the right pointer. Final beat: both cells green and an answer chip.

2. ARRAY SCAN WITH A HASH MAP
   Pointer i slides right; the "need" chip updates every step; the map is looked up and either a
   hit flashes green (MapViz.hit) or a miss shakes red (MapViz.miss). On a miss the current value
   is put into the map (MapViz.put, the row slides in); on a hit both cells turn green.

3. SLIDING WINDOW
   The window appears over one cell, grows with the right pointer, shrinks with the left
   (ArrayViz.window / move_window); the sum chip updates on every grow and shrink.

4. STACK (brackets, monotonic)
   Push drops in from above, pop lifts out of the pile and the matching pair flashes green;
   a mismatch flashes red. Keep the stack beside the array, never on top of it.

5. QUEUE AND BFS
   The queue sits beside the graph. Enqueue shows the node amber (active), dequeue turns it green
   and its neighbours become amber as they are queued.

6. DFS AND RECURSION
   The stack sits beside the tree or graph; the current node is amber, a finished node is green.

7. BINARY SEARCH
   Left, mid and right pointers; the discarded half turns grey; a chip shows the target.

8. LINKED LIST
   The curr pointer hops node to node; a relink redraws the arrow; remove fades the node and
   bridges the gap.

9. DP TABLE
   The grid fills in dependency order with a link arrow from every cell it reads; base cells are
   shaded; the final cell is highlighted.

10. HEAP AND SORTING
    Sorted cells turn green as the sorted part grows; a pivot is red; the two swapped values trade
    places and both cells flash.

11. BRUTE FORCE VS SMART
    Same structure in both scenes, with a "checks so far" chip counting up in the brute-force scene
    and staying at n in the smart one.

ANALOGY BANK (use one or adapt it, and come back to it in every stage)
stack = a pile of plates; queue = a line for ice cream; map = a notebook with name tags;
two pointers = two friends walking in from both ends of a bridge; window = a train window sliding
along; binary search = the guess-the-number game; BFS = ripples spreading in a pond;
DFS = exploring a maze to the end before turning back; DP = writing answers in a notebook so we
never solve the same thing twice; linked list = a treasure hunt where each clue says where the
next one is; heap = a tournament where the champion sits on top.

CONSISTENCY REQUIREMENTS
- The same structure keeps the same colours, lane and size in every scene it appears.
- Amber = looking at it now, green = found / done, red = wrong, grey = finished or discarded.
- Every scene with a structure changes something in every beat. Static display is not teaching.
